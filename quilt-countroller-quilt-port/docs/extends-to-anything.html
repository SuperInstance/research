The Countroller extends to anything

quilt-Countroller is a 5×5 LED matrix, a joystick, three buttons, and two buzzers on a Raspberry Pi Pico W. 32 cells. 32 typed links. The smallest possible hello-world of the Quilt substrate. The same cell-graph ports to anything.

The thesis

Every program can be Quilt-ported because Quilt is a visualization and intermediation layer for IO. The Countroller's 5×5 LED matrix is small enough to be canonical — the minimum cell-graph that demonstrates the substrate. Once you have the 32 cells, you can refactor any program into cells. Every program becomes a spreadsheet you can watch.

The 32 cells (the canonical substrate)

Inputs (4 cells)

  • joystick — (x, y) in [-1, 1]
  • button_a — press count
  • button_b — press count
  • joystick_button — center click

Outputs (28 cells)

  • buzzer_1, buzzer_2 — frequency
  • oled — text message

The 5 ports — same cell-graph, every runtime

🪛Pico firmware

Real hardware. WS2812 LEDs, ADC joystick, GPIO buttons, PWM buzzers, I2C OLED. Upstream C port on Pico SDK. The same 32 cells, the same witness chain, the same typed LINKs.

language: C / Pico SDK

🐍Python simulator

Pure Python. No hardware needed. Runs the same cell-graph in any 3.10+ interpreter. Used for tests, demos, and the witness replay mechanism. This is the reference port.

status: ✓ shipped (28 tests passing)

⚡Rust / no_std

Same cell-graph on Rust + the Quilt-ESP32 / Quilt-Pico runtime. ~3KB flash headroom. The substrate compiles to bare metal; the witness chain persists across reboots.

language: Rust + no_std + embedded HAL

🌐TypeScript / browser

Same cells, canvas pixels instead of NeoPixels. WebBluetooth connects to a real Pico for live data. WebGPU-accelerated render for large matrices. The browser becomes the simulator.

language: TypeScript + WebGPU + WebBluetooth

📡JSON-API

The cell-graph exposed as REST. Deploy to a Cloudflare Worker; the same endpoint contract works against the Python simulator, the Pico firmware, or the Rust runtime. GET /cells, POST /cells/<addr>/effect, GET /witness.

language: Python stdlib HTTP server / Cloudflare Workers

The pattern: ports to anything

The 32 cells aren't bound to LEDs. They describe an IO fabric. Replace the NeoPixels with:

  • Robot joint positions — 25 servos in a 5×5 grid; LED cells become joint angles, joystick becomes the controller
  • MIDI notes in a DAW — 25 channels of a step sequencer; LED cells become gate states, joystick becomes the tempo knob, buttons become play/stop/record
  • Token positions in an LLM prompt — 25 most-recent tokens; LED cells become attention scores, joystick becomes cursor, buttons become submit/regenerate
  • Portfolio positions in a trading app — 25 positions; LED cells become P&L heat, joystick becomes allocation slider, buttons become buy/sell
  • Browser canvas pixels — 25 tiles of a UI; LED cells become tile colors, joystick becomes cursor, buttons become action triggers

One cell schema. N substrates. That's the polyformalism payoff — the Quilt becomes the intermediate layer, and the same visual contract ports to anything.

The witness chain

Every state change appends to a witness chain. The chain is append-only, witness-stamped, and replayable. The same witness log format works across all 5 ports — replay a session recorded on the Pico in the browser, replay a browser session on the Rust firmware, replay a Rust session in the Python simulator.

The far-future first principles

The far-future version of this is:

  • Every program is a cell-graph. The substrate is universal.
  • Every cell is observable — frame timing, memory, witness chain.
  • Every IO port becomes a typed LINK. Every substrate becomes a cell value.
  • The Quilt is the intermediate layer — never the runtime, always the visualization.
  • Quilt-portable means: the same cell-graph runs in Pico, browser, server, robot, DAW, trading app.
  • The CUDA-Q planning layer proposes which cells to LINK. Classical substrate commits.
  • Quilt work backwards from far-future application first: what does the spreadsheet of the year 2032 look like? The answer: a Countroller, but with a million cells.
